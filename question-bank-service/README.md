# 题库服务台（电脑版）

独立的 Tauri 2 + React + Rust 桌面软件。原答题软件继续在根目录开发；本文件夹只制作电脑服务端，不包含 Android 工程。

## 启动与构建

在项目根目录安装依赖后：

```powershell
npm run service:dev
npm run service:build
```

也可以进入本文件夹执行 `npm install`，再运行 `npm run tauri:dev` 或 `npm run tauri:build`。电脑需要 Tauri 2 的 Windows 构建环境（Rust、MSVC、WebView2）。应用使用仓库已有的图标和 indexmap 补丁，单独复制本文件夹时需一并调整这些相对路径。

## 使用流程

1. 在“发布目录”添加文件夹，每一行选择数据类型，并勾选是否启用。
2. 点击“检查目录内容”，检查题库、知识库、值班表、软件包数量与无效文件提示。
3. 在“发布目录”页底部展开“本地服务设置”，配置监听 IP、本地端口和访问密钥，默认 `127.0.0.1:18080`。
4. 在自己的第三方 frp 软件中选择 **TCP** 转发，将本地目标指向 `127.0.0.1:18080` 或你修改后的本地地址和端口。客户端的题库下载和内容同步使用 HTTP/HTTPS，底层为 TCP；UDP 仅支持专用读取协议，不用于内容同步。本软件不配置、启动或停止第三方 frp。
5. 保存并启动服务，在“访问测试”直接粘贴第三方提供的完整地址，例如 `frp-sea.com:65079` 或 `https://服务器地址:端口`，点击“测试连接”。软件自动读取地址中的端口，不需要单独填写公网端口。服务运行时也可测试。主题可以随时切换且自动保存。
6. 在原答题软件“设置 → 数据来源”点击“添加来源”，选择“电脑服务”，填写名称、公网链接和相同访问密钥，测试后保存。GitHub、Gitee 在界面统一为“软件更新”类型，按链接自动识别平台，同时继续提供题库和软件更新；默认仍是独立来源，可停用、排序、编辑或删除。删除不会清除本地已导入的数据。
7. “内容同步”中的“软件更新”开关只控制软件检查和下载，不影响题库。题库获取与刷新由“题库下载／题库管理”负责，设置中不再获取题库。公共值班表只获取、不上传、不使用空间 ID；个人内容（知识库、总结、AI 聊天）按空间 ID 手动双向合并。启动、修改设置和恢复网络均不自动同步，成功或失败通过全局 Toast 通知。

电脑必须在线，服务和隧道必须运行，其他设备才能获取新数据。已下载题库及图片继续在本机使用。

## 关闭窗口与托盘

点击窗口右上角的关闭按钮（或按 Alt+F4）会收起到系统托盘，已启动的题库服务继续在后台运行，不释放监听端口。

- 左键点击或双击托盘图标，或右键选择“打开题库服务台”，可恢复主窗口；最小化的窗口也会恢复并获得焦点。
- 右键托盘图标选择“退出”，才会停止服务、保存流量记录并退出程序。
- 界面中的“关闭服务”仍只停止题库服务，服务台窗口和托盘图标继续保留。

## 发布目录格式

每行路径对应一个目录，可添加多个同类型目录。文件路径和挂载 ID 共同标识资源，同名题库互不覆盖。只读取启用目录中的 JSON、Markdown、TXT 和 PNG/JPEG/GIF/WebP；隐藏路径、越界路径、超出根目录的符号链接不允许访问。单文件最大 32 MiB，单目录最多 10000 个允许文件，最多 12 层。

题库资源统一位于 `Question_bank`：`public/banks` 存放公开内置题库，`private/Question` 存放原有私人题库，`private/Excel`、`private/Knowledge` 保留原有表格与知识资料。服务台可按需挂载 `Question_bank/public/banks` 或 `Question_bank/private/Question`，也可挂载整个 `Question_bank` 递归扫描题库 JSON。

```text
题库目录/
  第一套题/
    第一套题.json       # name、questions；题干支持 question 或 content
    image/
      1-1.png         # 第 1 题第 1 张图，兼容已有命名
      1-2.png
```

题目中的相对 `images` 路径以题库 JSON 所在位置为基准。客户端将图片转为本地数据后再完成导入；图片失败时本次导入报错，不替换已有题库。

知识库支持 UTF-8 `.md`、`.txt`，或单条文档 JSON：

```json
{"title":"配电知识","content":"正文内容"}
```

知识库条目的分类取发布目录名称。值班表使用现有的 JSON 结构（`name`、`shifts`，可附带 `drills`、`roles`）。不直接发布 Excel 文件；先在答题软件转换/导出为值班表 JSON。

## 第三方地址测试

软件只保留“发布目录”和“流量与历史”两页，没有隧道配置、frpc 程序选择、证书设置或隧道进程管理。第三方 frp 软件独立运行。

访问链接示例：`frp-sea.com:65079`、`https://bank.example.com:65079`。不填写协议时按 HTTP 处理；端口直接从地址读取，也支持部署路径前缀及带方括号的 IPv6 地址。测试会访问该地址下的 `/api/v1/health`，携带本地配置的访问密钥，检查题库服务标识和接口版本。

结果区显示成功/失败、实际测试 URL、耗时和失败原因。密钥无效、接口不存在、返回其他网站、版本不兼容都视为测试失败，并与完全无法连接区分。连接超时最多 8 秒，不忽略 HTTPS 证书错误，不自动跟随重定向。测试只表示从当前电脑访问该地址的本次结果，其他网络的可达性需在对应设备确认。

SakuraFrp 的部分节点禁止明文 HTTP，会返回 `Server: SakuraFrp`、`HTTP 501 Not Implemented`。这表示请求被节点拦截，不表示题库服务缺少健康检查接口。此时应保留 TCP 隧道，在第三方客户端启用“自动 HTTPS”并配置有效证书，重启隧道后改用 `https://服务器地址:端口`；本地目标仍为 HTTP 服务的 `127.0.0.1:18080`。软件会显示具体原因并提供“填入 HTTPS 地址”按钮，但不会跳过证书校验或将拦截页面当作连接成功。仅修改 URL 不能替代隧道的 HTTPS 配置。参考 [SakuraFrp 自动 HTTPS 文档](https://doc.natfrp.com/frpc/auto-https.html)。

测试过的完整地址自动保存，服务运行时也可修改；本地监听设置需要停止服务后保存。旧配置中单独保存的公网端口会在启动时合并进地址并清空，之后不再覆盖新输入的端口。旧配置中的内置隧道字段被忽略，后续保存时移除。

UDP 读取协议：发送 UTF-8 JSON `{"token":"访问密钥","path":"/bank-index.json","offset":0}`。健康检查 `/api/v1/health` 直接返回 JSON；其他读取接口返回 `status`、`offset`、`total`、`encoding:"base64"` 和 `data`。每次最多返回 768 字节正文，使用 offset 续读；专用客户端负责超时重试、顺序组装和最终哈希校验。同步写入使用 HTTP/HTTPS 的 PUT，不通过 UDP 写入。

## 数据接口与同步规则

### 软件包目录

添加 `Question_bank/private/Package` 并把类型选为“软件包”。不自动复制或编译文件；将安装包放进去后，客户端下次检查更新会读取当前目录。替换文件时先使用临时扩展名写入，完成后再改为最终文件名，避免发布正在写入的文件。

推荐命名：`Answer_Test_v0.4.4_build20261021_arm64.apk`、`Answer_Test_v0.4.4_build20261021_x64.exe`。也兼容 `Answer_Test_v0.4.4_2026102101_x64.exe`；构建号为 1—20 位数字，短构建号必须带 `build`、`b` 或“构建”前缀，无前缀构建号至少 6 位。版本号格式为三段或四段数字。优先比较版本号，同版本再按数值比较构建号，不使用文件修改时间判断版本。

支持 APK、EXE、MSI、DMG、AppImage 和带 windows/macos/linux 标记的 ZIP，单文件最多 2 GiB，以流式方式下载。缺少版本号或构建号、预发布/调试包、无平台 ZIP 和空文件会跳过并显示检查提示。客户端仅选择当前平台和架构可用的正式包；不同版本、不同构建之间不互作备用下载。所有安装包下载仍需访问密钥，普通题库目录不会因此开放 EXE/APK。

Android 沿用下载后调用系统安装器的流程；桌面版下载后打开下载目录，由用户关闭旧程序后手动安装或替换便携版。要完整使用新的平台选择与桌面鉴权下载行为，客户端也需要包含本次代码更新。

HTTP 请求使用 `Authorization: Bearer <访问密钥>`。所有接口均需要密钥，浏览器跨域预检 OPTIONS 除外。

| 接口 | 用途 |
|---|---|
| `GET /api/v1/health` | 连接与版本检查 |
| `GET /bank-index.json` | 兼容原软件的题库索引 |
| `GET /duty-index.json` | 值班表索引 |
| `GET /app-update.json` | 软件包更新清单，按版本号与构建号分组 |
| `GET /api/v1/knowledge` | 已发布知识文档 |
| `GET /api/v1/catalog` | 发布资源与无效文件提示 |
| `GET /files/{目录ID}/{相对路径}` | 只读下载 |
| `GET /api/v1/images/{目录ID}/{相对路径}` | 图片索引 |
| `GET/PUT /api/v1/sync/{空间ID}/{类型}` | 个人内容独立同步；当前客户端仅使用 knowledge、summaries、chat |

个人同步只支持 `knowledge`、`summaries`、`chat`。题库、值班表只从发布目录的公共索引和资源 GET 接口获取，不上传到同步存储。旧版 `/api/v1/sync/<space>/duty`、`/api/v1/sync/<space>/banks` 和 `/api/v1/bank-sync/` 接口均返回 HTTP 410；历史存档保留，但不读取、展示或继续写入。每台设备初始生成不同的空间 ID；同一用户需要多设备共享个人内容时手动填写相同的空间 ID，公共资源不受空间影响。访问密钥和空间 ID 均属于访问凭据；这里没有独立用户账号系统，不适合用一个公共密钥向互不信任的用户提供私有存储。

GET 返回 `{revision,data}`，PUT 提交 `{baseRevision,data}`；版本冲突返回 HTTP 409 和当前内容。客户端重新合并并最多尝试三次。知识条目和会话按稳定 ID 与更新时间合并；会话内的消息也按 ID 合并；总结按历史版本 ID 合并，并携带 `deleted` 删除标记，防止旧远端版本恢复已删除总结。知识条目和聊天记录的删除仍仅影响本机。删除最后一版总结后显示空状态，须主动重新生成。运行中的总结跳过本轮同步。切换来源或关闭开关后，旧请求结果不再写入本地。短暂网络故障只自动重试一次 GET；PUT 超时不重复提交，提示结果尚未确认，由下一次手动同步核对。

同步空间存在服务端应用数据目录的 `sync/` 下，不回写你发布的文件夹，也不经过公开文件路由。同步不包含 AI API 密钥、判题设置或整个客户端配置。客户端首次向某空间同步时会上传启用类别的现有内容；公网同步请配置 HTTPS。

电脑版“发布目录”页的“同步存储”概览仅显示知识库、总结、AI 聊天三类内容及其空间、版本、大小和最近写入时间。展开后每 10 秒读取本机存储统计，不触发客户端资料同步；题库和值班表不计入空间数量或大小。查看概览不需要启动服务，也不改动已保存内容。

原答题软件设置中的“数据来源”和“内容同步”默认折叠。来源条目的排序、删除收在“管理”中，编辑时才展开表单；同步空间 ID 和规则位于“同步空间与规则”内。

## 公共题库与值班表获取

题库由“题库下载／题库管理”读取已启用来源的 `bank-index.json` 并判断获取与更新。设置中的“获取值班表”只读取 `duty-index.json`。两类资源均不上传、不发送个人空间 ID；使用现有访问密钥鉴权，公网继续使用 HTTPS。

题库索引每项支持 `bankId`（稳定标识）和 `updatedAt`（UTC ISO 时间戳；也兼容秒／毫秒数字）。相同 `bankId` 先按 JSON hash 与图片清单分组，同版本去重并保留来源顺序，再按每组最新时间戳选择版本。没有 ID 的旧索引按文件名兼容，不按显示名称合并；无时间戳时不声称来源更新，已有时间的本机版本不会被无时间的来源覆盖。不同内容同时间时按来源顺序选择。下载只使用选中源和同版本镜像，并校验实际 SHA-256 或 Git blob SHA-1，防止旧镜像替换新版本。

服务台目录接口返回文件与关联图片的最新修改时间。仓库发布前运行 `npm run update:bank-index`，离线重算本地文件 SHA-256、稳定 ID 和时间戳；内容未变时保留时间戳，不以每次扫描时间冒充新版本。系统与私人题库的下载及图片索引分别使用 `Question_bank/public/banks/`、`Question_bank/private/Question/`，目录迁移不改变题库 ID、hash 和版本时间。

题库下载与管理按稳定标识识别已获取版本，切换来源不会仅因来源地址不同重复导入；时间戳描述的是来源版本，不使用本机编辑时间判断发布新旧。值班表更新继续保留本机编辑副本。

值班表在用户打开下载面板时获取一次列表，或点击刷新/重试时再次获取；空目录、404、请求失败和本地资料缺失均不会触发循环请求。题库下载页只在主动进入页面或点击刷新时获取列表，本地题库或来源变化不自动刷新远程目录；题库管理页进入时仅加载本机资料，远程更新检查由用户点击刷新触发。

两个页面入口使用紧凑的顶部导航。发布页采用左右等宽、整体等高的工作区：左侧固定目录标题、统计和底部操作，仅目录列表独立滚动；右侧上方为访问测试，下方为默认展开的同步存储，两者内容分别滚动。目录数量增加不会把同步存储推到页面下方，本地设置展开时也为同步区保留空间。较窄窗口改为单列，目录列表仍有高度限制。流量页保留累计统计、趋势和最近请求，移除每日历史表格；最近请求使用完整内容宽度，上传与下载正文流量分列显示，并明确服务端视角。每日统计继续作为七天趋势的数据来源。

全局滚动条采用独立浮层，原生滚动容器保留，滚动条不占宽度或高度，也不预留 gutter。页面和嵌套列表支持水平、垂直滚动及键盘、滑块拖动，颜色跟随主题。

## 流量与历史

“流量与历史”页提供上传、下载、请求数、1 小时/24 小时/7 天折线图、每日汇总和请求记录。上传是服务端发给客户端的正文，下载是客户端发给服务端的正文，均不含 HTTP/TLS/隧道开销，不是网卡计费统计。UDP 按实际提交给 socket 的数据报统计。

流量页优先展示请求列表：统计值与时间范围合并为一行，移除重复说明；趋势图固定为 132px 高，按实际容器宽度绘制，刻度保持 12px。上传、下载曲线下方使用向下渐隐的面积填充。请求面板占据剩余高度并独立滚动，表头固定，方向标识与请求路径同行；统计口径保留在悬停提示中。

流量每 5 秒保存，正常停止时立即保存；分钟数据保留 7 天，每日 UTC 汇总持续保留，最近请求保留并展示最近 500 条。最近请求支持按上传、下载方向筛选，流量分列显示；PUT 归入接收客户端数据，其余只读请求归入发送给客户端，请求和响应正文仍分别记入两列。异常断电可能损失最后 5 秒统计。配置和历史保存在 Tauri 的应用数据目录，界面显示实际路径。

## 验证

```powershell
npm run test:data-source
cargo test --offline --manifest-path question-bank-service/src-tauri/Cargo.toml
```

客户端回归覆盖同步开关隔离、版本冲突重试、重复同步、图片缓存、来源切换和密钥隔离；Rust 测试使用真实本地 TCP/UDP 监听，覆盖鉴权、中文资源下载、目录越界、同步空间隔离、并发版本冲突、停止释放端口和历史恢复。地址测试覆盖链接和端口处理、连接成功、密钥错误、错误网站、接口不存在、超时、拒绝连接及重定向。真实公网结果需提供第三方链接后验证。

独立联调可使用 `question-bank-service.exe --data-dir <隔离配置目录>` 打开桌面端，或 `question-bank-service.exe --headless <隔离配置目录>` 仅启动接口。目录内需准备 config.json。`scripts/verify-service-live.ts` 通过原客户端适配代码访问真实服务，只允许 loopback 地址，向随机同步空间写入合成测试内容：

```powershell
$env:SERVICE_TEST_URL = 'http://127.0.0.1:18081'
$env:SERVICE_TEST_TOKEN = '隔离测试服务的访问密钥'
npx tsx scripts/verify-service-live.ts
```
